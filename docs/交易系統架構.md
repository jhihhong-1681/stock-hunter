## 1. 系統目的與設計原則

**目的**：幫阿紘在美股帳戶（正股 + 期權，追求報酬）執行「下跌才買」：只在股價從高點明顯回檔後才進場，分批往下加碼，用固定紀律止損，並用基本面過濾掉「便宜是有原因」的標的。

**設計原則**
- **價格訊號 + 基本面**為依據，不看估值（阿紘定）。
- **系統只輔助，買賣由阿紘決定**。止盈完全由阿紘判斷，系統不替他決定；進場門檻 20% 只是參考，阿紘依個股波動率自己判斷。
- **透明**：每個分數、判定都附理由，不做黑箱。
- **只用靜態資料檔**：Streamlit 頁面只讀 repo 裡的 JSON，不在頁面上現場抓資料（Yahoo 在雲端 Claude 環境與部分情境連不到、也容易被限流）。
- **美股限定**（不做台股），小型股可以，但要過流動性門檻。
- **首批價、已買批數完全以成交紀錄 `trades.js` 為準**，不用 Google Sheet 的「第一筆建倉」欄位（那個欄位可能是錯的）。

## 2. 整體架構與資料流

### 2.1 角色分工

| 執行者 | 做什麼 | 為什麼放在這裡 |
|---|---|---|
| 阿紘桌機（本機排程） | Firstrade 未成交訂單與成交紀錄 → `pending_orders.js`、`trades.js` | 需要已登入的 Chrome，絕不代打密碼 |
| Claude 雲端排程（台北 13:30） | 讀 Google Sheet → 每日快照（`holdings.js` 等）、新正股登記類型、**選股新聞評分** | Claude 能讀 Drive、能 WebSearch；但**連不到 Yahoo/SEC** |
| GitHub Actions | 抓股價與財報（yfinance）→ 算訊號、篩選、回測 | 只有 Streamlit Cloud 與 Actions 抓得到 Yahoo |
| Streamlit Cloud | 顯示頁面（`pages/12_交易系統.py`），只讀 repo 的 JSON | push main 自動部署 |

### 2.2 每日時序（台北時間）

```
13:30  Claude 雲端排程：讀 Sheet → 寫 holdings.js 等 → push main
         │
         ├─(holdings.js 變動觸發)→ GitHub Actions「Compute Trading Signals」
         │       scripts/compute_signals.py → data/trading_signals.json
         │       （備援 cron：14:30 週一到週五）
         │
         └─(holdings.js 變動觸發)→ GitHub Actions「Daily Screener」（約 10 分鐘）
                 scripts/screen_universe.py → data/screener.json 等
                 （備援 cron：14:40 週一到週五）
         │
13:30 排程續跑 step 12b：每 60 秒檢查 screener.json 的 generated 有沒有更新（最多等 25 分鐘）
         → 取成長型前 14 + 成熟型前 6 共 20 檔 → WebSearch 評新聞 → 寫 data/news_scores.json → push main
         │
Streamlit：頁面載入時讀 screener.json + news_scores.json，合併、重排後顯示
```

- 兩個 workflow 都設了 `concurrency`，新的觸發會取消舊的（`cancel-in-progress`）。
- workflow 最後都會 `git pull --rebase` 再 push；**新增輸出檔一定要同步加進 workflow 的 `git add`**（歷史上漏過好幾次，現在 screener 用 `data/*_cache.json` 萬用字元）。

### 2.3 為什麼這樣切

- 價格/財報（重、要 Yahoo）→ Actions 算好存檔。
- 新聞（要理解文字、判斷）→ Claude 雲端排程用 WebSearch。
- 顯示 → Streamlit 只讀檔，快且不會因 Yahoo 限流而掛掉。
- 規則（純函式）集中在 `utils/`，Actions 與頁面共用同一份，避免兩邊邏輯不一致。

## 3. 交易規則

規則定義在 `utils/trading_system.py` 的 `Rules` 與 `OptionRules`。

### 3.1 正股

| 項目 | 規則 | 程式參數 |
|---|---|---|
| 參考高點 | 近 **26 週 = 130 個交易日**的最高收盤（2026-10-22 由 52 週改） | `high_window=130` |
| 進場 | 現價距參考高點回檔 **≥ 20%**（可依個股波動率自行判斷） | `entry_drop=0.20` |
| 金字塔三批 | 第 1／2／3 批 = **NT$2 萬／3 萬／4 萬**，最多 3 批 | `tranches_ntd=(20000,30000,40000)` |
| 加碼方式 A | 下一批在「**上一批買進價**再跌 20%」（2026-10-22 由 12% 改 20%；是跟上一批比，不是跟首批比） | `add_step=0.20` |
| 加碼方式 B | 首批後上漲、再從高點回落 20–30%（採 25%；要先比均價漲過 10% 才算「上漲過」） | `rebound_pullback=0.25`、`rebound_min_gain=0.10` |
| 止損 | 現價 ≤ **首批買入價 × 50%** → 全部出清（中間加碼幾次都不影響止損價） | `stop_from_first=0.50` |
| 止損後再進場 | 從**止損價**再跌 30%，且基本面沒有太大改變 → 開新一輪（新的首批價、批數歸零） | `reentry_drop=0.30` |
| 止盈 | **阿紘自己判斷**，系統不決定。（回測才需要假設，用 `take_profit=0.50`，僅回測使用） | — |
| 檔數目標 | 正股 5–10 檔、期權 5–10 檔 | — |
| 舊部位 | 批數超過 3 批的舊部位**不處理** | — |
| 匯率 | 固定 31（阿紘固定值） | `usd_twd=31` |

**「一輪」（episode）的定義**（`episodes()`）：從空手買進到全部賣光為一輪。同一天的買進併成一批（`tranche_groups()`，加權均價）。成交紀錄沒有時間時，同一天**先算買再算賣**（否則「當天先加碼再賣」會被誤判成先賣光再重開）。已買批數 = 目前這一輪的買進天數。

**止損計算範例**：首批價 $100 → 止損價 $50；止損後再進場價 = $50 × 0.7 = $35。

**加碼價範例**：首批 $100，第 2 批在 $80（上一批 −20%），第 3 批在 $64。

### 3.2 期權

期權是**獨立的短線工具**（不套用金字塔）：
- 標的必須已在進場區（距 26 週高點回檔 ≥ 20%）。
- 標的基本面判定不是「排除」。
- 買進時距到期 **≥ 14 天**（14 天內歷史勝率僅 25%）。
- **價外程度、單筆金額、總成本占比都不設上限**（價外樂透也可以），只顯示不檢查。
- 期權檔數上限 10 檔（現有超過時只提示，不擋）。
- **權利金虧損達 60% 就出場**。
- 現有期權部位不處理。
- 阿紘收到報牌可貼到「期權檢查」分頁（`utils/option_parse.py` 解析 OCC 代碼、中英文描述），系統逐項對照規則（`check_option()`）。

價外程度標籤（`moneyness()`）：價內（OTM < −3%）、價平（±3%）、輕微價外（≤10%）、價外樂透（>10%）。

## 4. 基本面判定（`utils/fundamentals.py`）

**原則**：優先看成長與獲利，再看財務體質，**不看估值**。

### 4.1 兩層分類

1. **公司類型**：成長型／成熟型（第 5 節）。
2. **獲利狀態（track）**：近四季營業利益加總 > 0 = 「已獲利型」；≤ 0 = 「成長虧損型」。虧損**不是**排除原因，改看毛利率、現金、稀釋。

### 4.2 判定規則（`evaluate()`）

判定有三級：**通過（0）／警示（1）／排除（2）**，另有「資料不足」（少於 4 季營收）。多條規則取最嚴重者。

**成長型**
- 營收年增率（最新一季 vs 4 季前）：負 → 排除；< 40% → 警示；算不出來 → 警示。
- 若為成長虧損型：毛利率 < 20% → 警示；毛利率比一年前掉 > 5 個百分點 → 警示；營業利益率變差且為負 → 警示（虧損擴大）；營業利益率改善 → 備註「虧損在收斂」。
- 若為已獲利型：營業利益率比一年前掉 > 5 點 → 警示。

**成熟型**
- 營收年增率 < 0 → 警示；連兩季為負 → 排除。
- 成長虧損型（成熟卻還在虧損）→ 警示。
- 營業利益率比一年前掉 > 5 點 → 警示。

**財務體質（兩種類型共用）**
- 僅對**成長虧損型**：現金可撐月數 = 現金 ÷ 近兩季平均每季燒錢 × 3。< 12 個月 → 排除（**有實質程度高/中的巨頭合作則降為警示**）；12–24 個月 → 警示。
- 年化股本稀釋 > 30% → 警示。
- 僅對成長虧損型且在燒錢：總負債 ÷ 現金 > 2 → 警示。
- 賺錢公司不用「現金可撐月數」與「負債/現金」（賺錢但單季自由現金流為負、本來就有債是正常的）。

### 4.3 巨頭合作（`data/partnerships.json`）

- 人工維護、**每筆附出處、只放公開資訊**。
- 實質程度分「高／中／低」。只有「高／中」算保障（低 = 產品整合、意向、路徑，不採計）。
- 作用僅一個：把「現金撐不夠久」從「排除」降一級成「警示」。
- 選股雷達的新候選**預設沒有合作資料**；只有阿紘要求時才去研究並登記。

### 4.4 其他資料檔
- `data/company_profiles.json`：手動登記的公司類型（成長型／成熟型／ETF）與理由。登記的**優先於**自動分類。新正股由每日快照自動登記（SNAPSHOT_TASK.md「公司類型登記」，只新增不改既有）。
- `data/conviction.json`：高信念清單，**目前先不用**。

## 5. 公司類型分類（`utils/classify.py`）

**為什麼要分**：成長型與成熟型的合理成長率、獲利結構完全不同，放在一起評分會失真。阿紘要兩種都要（成熟股被錯殺可能是勝率更高的買點），所以**分兩個排行榜，各自排名**，權重不調整。

**阿紘的判斷標準**：市占、增長、市值、規模。其中**市占沒有可靠免費資料，無法自動化**，用「市值 + 營收規模 + 產業」當代理；龍頭公司請手動登記到 `company_profiles.json`（登記的優先）。

### 5.1 計分

`成長分 g`
| 條件 | 加分 |
|---|---|
| 營收年增率 ≥ 100% | +4 |
| ≥ 40% | +3 |
| ≥ 25% | +2 |
| ≥ 15% | +1 |
| < 0 | −1 |
| 近 3 季營收連續季增 | +1 |
| 成長虧損型且年增率 ≥ 25% | +1 |
| 近四季營收 < \$2000 萬且市值 ≥ \$3 億（還沒有實質營收、靠未來估值） | +3 |

`成熟分 m`
| 條件 | 加分 |
|---|---|
| 市值 ≥ \$500 億 | +3 |
| ≥ \$100 億 | +2 |
| ≥ \$30 億 | +1 |
| 近四季營收 ≥ \$100 億 | +2 |
| ≥ \$50 億 | +1 |
| < \$2 億 | −1 |
| 防禦型產業（Utilities、Consumer Defensive、Real Estate） | +1 |

**判定**：`net = g − m`，`net ≥ 1` → 成長型，否則成熟型。

### 5.2 把握度與遲滯

- 把握度依 `|net − 0.5|`：≥ 3 → 高；≥ 1.5 → 中；否則低。市值或年增率缺 → 一律低。
- **把握度「低」時沿用上次的分類**（存在 `data/profile_cache.json` 的 `type`），避免同一檔在兩類之間每天跳動。
- 已登記的標的：來源標「已登記」、把握度「高」。未登記的標「自動推定」並附判斷依據（`kind_why`）。

### 5.3 市值與產業的取得
- `fetch_profile()`：yfinance `.info`（市值、sector、industry）。**Actions 上 Yahoo 常回 401 "Invalid Crumb"**（2026-10-22 發現，曾導致全部市值為空）→ 現在同時只開 2 個執行緒、失敗重試 3 次（間隔 1.5/3/4.5 秒）、市值抓不到時改用 `fast_info`（不需 crumb）。
- 快取 30 天（`PROFILE_TTL_DAYS`），存 `data/profile_cache.json`。執行記錄會印出「市值取得 N/總數」，可一眼看出有沒有壞。
- 2026-10-22 實測：224 檔候選中 221 檔有市值與產業。

## 6. 選股雷達（`scripts/screen_universe.py` → `data/screener.json`）

### 6.1 流程

1. **名單**：NASDAQ Trader 官方兩份清單（`nasdaqlisted.txt`、`otherlisted.txt`）。排除：ETF、Test Issue、權證／權利／Units／特別股／債券／SPAC（名稱關鍵字過濾）。約數千檔，少於 2000 檔視為異常並中止。
2. **價格**：yfinance 每 150 檔一批下載 2 年日線。
3. **流動性與資料量過濾**（任一不過就剔除）
   - 至少 250 日資料（`MIN_HISTORY`）
   - 股價 ≥ \$3（`MIN_PRICE`）
   - 近 50 日平均成交額 ≥ US\$500 萬（`MIN_DOLLAR_VOL`）
4. **進場區**：`scan_symbol()` 算距 130 日高點回檔、年化波動率（用一年資料）、回檔÷波動率。回檔 ≥ 20% 才成為候選。**已持有的排除**。
5. **財報**（`get_fundamentals()`）：對候選抓季報（損益、資產負債、現金流），快取 7 天（`data/fundamentals_cache.json`），單日最多抓 1200 檔，**按最超跌優先**。
6. **市值／產業**（第 5.3 節）。
7. **分類 → 基本面判定**：先 `evaluate(..., kind=None)` 取指標（年增率、獲利狀態）→ `classify()` → 帶著類型再 `evaluate()` 得判定。
8. **基本面分、價格分** → 預評分（預期資金與消息先放中性 50）。
9. **預期與資金**（`fetch_flow()`）：只對預評分**前 80 名**抓（每檔多打好幾次 Yahoo）：分析師近 30 天升/降評、內部人近 90 天買賣、空單比例、下次財報日。快取 3 天（`data/flow_cache.json`）。
10. **紅線**：基本面判定「排除」→ `veto`。
11. **排序輸出**：總分高到低，有紅線的排最後。依類型分別保留前 100 檔（其他類型 30 檔）。

### 6.2 輸出內容（`data/screener.json`）
- `generated`（UTC）、`price_date`、`weights`、`filters`、`stats`（各階段檔數、判定統計、分類統計、財報抓取成功/失敗數）。
- `candidates[]`：代號、名稱、現價、高點、回檔、波動率、回檔/波動率、成交額、60 日走勢、類型/來源/把握度/理由、市值、產業、近四季營收、判定與理由、指標、巨頭合作、各面向分數與理由、`quant_score`、`veto`、財報日倒數、`plan`（若首批以現價買入的建議股數、第 2/3 批價、止損價）、`is_new`（相對上次是否新出現）。

### 6.3 評分歷史與驗證（2026-10-22 起）
- `data/score_history/YYYY-MM-DD.json.gz`：**每天完整保存所有進入進場區的候選**（不只前 100 名），含各分項分數（基本面／價格／預期資金／量化總分）、判定、類型與把握度、產業、市值、營收年增、財報日倒數；新聞評分跑完後由模擬帳戶的 workflow 補進當天的檔（`news`）。（舊的 `data/score_history.json` 只有前 30 名，保留不再更新。）
- `scripts/score_returns.py`（`score_returns.yml`，台北 16:30）→ `data/score_returns.json`：補算後續 5／20／60／120 個交易日的報酬與對 SPY 的超額報酬，做**消融比較**：只有價格、只有基本面、價格＋基本面、完整（不含新聞）、完整＋新聞。每個快照日、每個類型把候選分 5 組，看最高分組 vs 最低分組的差距、高分組勝率、等級相關（IC）。頁面「進階 → 分數驗證」顯示；不到 10 個快照日只能參考。
- 分數的權重是判斷出來的，無法用歷史財報與新聞回測，所以靠這份往後累積的資料檢驗。

## 7. 評分系統（`utils/scoring.py`）

**總分 = 基本面 × 0.40 + 價格位置與止跌 × 0.35 + 預期與資金 × 0.05 + 消息 × 0.20**（阿紘 2026-10-22 定）。各面向 0–100。分數標籤：≥80 很強、≥65 不錯、≥50 普通、否則偏弱（`label()`）。

分段線性插值函式 `lin(x, [(x0,y0),...])`：x 落在兩點之間線性內插，超出範圍取端點。

### 7.1 基本面品質（40%）— `score_fundamental()`

三塊再加權：**成長 40%、獲利 30%、體質 30%**（缺的項目自動重新正規化）。

**成長 g**（營收年增率）
- 成長型曲線：−20%→0、0→10、25%→35、40%→55、60%→75、100%→92、200%→100。
- 成熟型曲線：−15%→0、0→35、5%→55、12%→75、25%→92、40%→100。
- 連續季增調整：`g ± 4×(季增為正季數 − 1)`，夾在 0–100。
- **小基期折價**：年增率 > 40% 時，近四季營收 < \$5000 萬 → ×0.6；< \$2 億 → ×0.85（授權收入、剛商業化的高成長可信度低）。

**獲利 p**：營業利益率水位(35%)、毛利率水位(25%)、利益率趨勢(40%，比一年前)。
- 營業利益率：−100%→0、−30%→25、0→45、10%→70、20%→88、35%→100。
- 毛利率：0→0、20%→35、40%→65、60%→90、80%→100。
- 趨勢：與一年前差 −10 點→0、0→50、+10 點→100。

**體質 safe**：現金可撐（60%）＋股本稀釋（40%）。
- 成長虧損型：不燒錢 = 100；否則可撐月數 0→0、12→20、24→70、36→100。已獲利型固定 85。
- 稀釋：0→100、5%→90、15%→60、30%→25、60%→0。

**封頂**
- 判定「警示」→ 最高 65 分；「排除」→ 最高 25；「資料不足」→ 最高 30。
- 金融股（Financial Services）→ 最高 60（營收含投資收益，年增率與毛利率不可比）。
- 完全算不出來 → 30 分並註明「財報資料不足」。

### 7.2 價格位置與止跌（35%）— `score_price()`

= **超跌程度 55% + 止跌跡象 45%**。

- **超跌程度**：用「回檔 ÷ 年化波動率」的倍數（越超跌越高）：0.2 倍→5、0.5→25、0.8→50、1.1→75、1.5→95、2.0→100。（同樣跌 30%，高波動股比低波動股「不算深」。）
- **止跌跡象**（避免接落下的刀）：
  - 離近 20 日低點反彈幅度（45%）：0→10、3%→45、8%→80、15%→90、30%→60、60%→30（反彈太多反而降分，代表已不是低點）。
  - 近 10 日報酬（35%）：−15%→0、−5%→35、0→60、5%→85、15%→70。
  - 近 10 日波動 ÷ 近 60 日波動（20%）：0.5→100、0.9→70、1.3→40、2.0→10（波動收斂代表賣壓減輕）。

### 7.3 預期與資金（5%）— `score_flow()`

起始 50，只對前 80 名有資料，沒資料 = 中性 50。
- 分析師近 30 天：每 1 次升評 +10、降評 −10（淨值夾在 ±25）。
- 內部人近 90 天有買進 +15；沒買進但賣出 ≥ 3 筆 −10。
- 空單比例 > 15% −5；> 25% −10。
- 結果夾在 0–100。

### 7.4 消息催化（20%）— `score_news()`
- 雲端排程給 −10 ~ +10，轉成 0–100：`(score + 10) × 5`。
- 沒評到 = 中性 50，並標「消息面未評」（**沒評到的名次不會因此被懲罰，也沒有加分**）。
- 有紅線（veto）→ 該面向 0 分，且總分排最後。

### 7.5 紅線（一票否決，排到最後）
- 基本面判定「排除」。
- 新聞掃描發現：going concern 警語、大量稀釋性增資或可轉債（約市值 10% 以上）、SEC／司法部調查或被控詐欺、收到退市通知、聲請破產保護。

### 7.6 財報日
**只標示，不扣分**（頁面卡片顯示「N 天後財報」）。

### 7.7 頁面如何合併新聞（`pages/12_交易系統.py: enrich()`）
Actions 算出的 `quant_score` 把消息面當 50；頁面讀 `news_scores.json`，**14 天內**的評分才採用，重算總分並重新排序。

## 8. 消息面評分（Claude 雲端排程 step 12b）

規則寫在 `portfolio-calendar/SNAPSHOT_TASK.md`。重點：

1. 等 Actions 的選股結果更新（比推上時間 T0 新；每 60 秒檢查，最多 25 分鐘，逾時用舊結果）。
2. 從 `candidates` 取「無紅線且判定非排除」的：**成長型前 14 + 成熟型前 6 = 20 檔**。
3. 每檔 WebSearch，**一律 `mode: "extended"`，至少 3 種查詢**（公司+代號+news+月份、press release/announces、analyst price target upgrade downgrade；必要時 8-K、investigation lawsuit）。只採**近 14 天、有明確出處網址**的消息；查不到 = 0 分，不猜、不用舊新聞湊。「只是宣布財報日」不算消息。
4. 評分尺度：+8~+10 重大合約/財報大幅超預期上調指引/重大核准；+4~+7 小幅超預期、較小合約、分析師大幅升評、內部人大額買進；+1~+3 輕微利多；0 無消息；−1~−3 輕微利空；−4~−7 財報不如預期、下修指引、客戶流失、高層離職、產品延遲；−8~−10 重大利空。
5. 律師事務所「代表投資人調查」通告**不是** SEC 調查，不構成紅線（−3~−5）；已提起的證券集體訴訟 −4~−6。
6. 寫入 `data/news_scores.json`（`scores[代號] = {score, label, summary, events[≤3], veto, asof}`），舊條目 14 天內保留。
7. 失敗不影響快照，只在結果摘要說明。

**已知問題與修正**：第一輪只用標準模式搜一次，結果全部 0 分（找不到有日期的新聞）→ 改成 extended 模式 + 多查詢後才找得到。

## 10. 回測

### 10.1 做了什麼
- 在 GitHub Actions 跑（`data/backtest_request.json` push 上 main 觸發 `.github/workflows/run_backtest.yml` → `scripts/run_backtest.py` → `data/backtest_*.json`）。
- 兩組標的：阿紘成交紀錄出現過的正股（`from_trades`，約 101 檔）、S&P 500（對照）；10 年日線。
- 網格參數：止盈寬度、進場深度、止損、加碼間距、參考高點區間（252 日 vs 130 日）。
- 單一標的獨立回測（`backtest()`）：收盤價成交、不含手續費與滑價；止損後等「止損價再跌 30%」才重新進場；止盈後有 40 個交易日冷卻。

### 10.2 可信度（務必注意）
- **只測價格規則**，沒有歷史基本面，「基本面沒大變」這個前提無法檢驗。
- **倖存者偏差**：`from_trades` 是阿紘買過的（多為後來還活著且受關注的股票），S&P 500 用的是現在的成分股。絕對報酬偏樂觀。
- 因此**只有相對比較**（止損 vs 不止損、止盈寬度、進場深度、加碼間距）比較可信。
- 回測的止盈是假設值，實際止盈由阿紘判斷。
- 評分系統的權重**沒有也無法回測**（無歷史財報與新聞），靠 `score_history.json` 日後用實際報酬檢驗。

## 13. 已知限制與風險（討論時請特別看）

1. **分數權重是判斷值**，沒有歷史驗證。40/35/5/20 是阿紘依偏好定的，可否站得住要靠 `score_history.json` 累積後檢驗。
2. **市占無法自動判斷**：龍頭但市值/營收不夠大的公司（例如特定產業的市占第一）可能被分錯，需手動登記。
3. **分類在邊界附近不穩**：把握度「低」的標的沿用上次分類，所以第一次分錯會延續（直到人工登記或條件改變）。目前約三成候選為「低」。
4. **Yahoo 資料品質與可得性**：財報欄位名稱不一、部分小型股缺資料（約 24 檔資料不足）；Actions 上 Yahoo 會 401/限流（已做重試與降併發，但不保證）。
5. **基本面門檻（成長型年增 ≥ 40%）**很硬：成長率剛好在 35–40% 的好公司會被標警示；而且是以「最新單季 vs 去年同季」判斷，單季波動會影響。
6. **新聞評分是 LLM 判斷**，有主觀與漏掉的風險（曾因查詢方式不對而全部 0 分）。只涵蓋前 20 名，其餘新聞面 = 中性 50。
7. **預期與資金只涵蓋前 80 名**（其餘中性 50），權重僅 5%，影響小。
8. **回測有倖存者偏差、無基本面**（見第 10 節）。
9. **金融股**基本面不可比，只做保守封頂（60 分），沒有專用指標。
10. **進場後的基本面惡化**：持股的基本面每天重算，但「止損後再進場需基本面沒大變」目前是提示文字，由阿紘判斷。
11. **流動性門檻**（股價 ≥ \$3、日均成交額 ≥ \$500 萬）對小型股偏寬，實際可成交量還要自己看。
12. **匯率固定 31**，與市場匯率有落差時 NT\$ 金額只是近似。
13. 財報日只標示不扣分：進場前遇到財報風險由阿紘自行判斷。

## 17. 模擬帳戶（紙上交易）— 驗證這套策略的未來績效

**目的**：把選股雷達的排行真的「買下去」，往後每天如實記錄，用來驗證策略。檔案：`utils/paper_trading.py`（規則）、`scripts/paper_trade.py`（執行）、`.github/workflows/paper_trade.yml`、輸出 `data/paper_portfolio.json`、頁面「🧪 模擬帳戶」。起算日 2026-10-21（選股資料日），v3 於 2026-10-22 重新建倉。

**設定**：本金 NT$100 萬，成長型約 70%／成熟型約 30%（預算 = 比重 × 目前總資產）；成長型最多 7 檔、成熟型最多 3 檔；匯率固定 31；**不做止盈**；對照組為同一天 100 萬全買 SPY。

**成交假設（v3，比 v2 保守）**：訊號都在收盤後產生，**預約單隔個交易日開盤成交**，買進加 0.3%、賣出減 0.3% 滑價（粗估跳空與買賣價差），不含手續費。止損也是收盤跌破才預約、隔日開盤出場，所以跳空時出場價可能比止損價差很多。每檔同時最多一張預約單。

**每天的流程**（Actions 於新聞評分 push 後或台北 15:15 備援觸發）
1. 取得每檔持股的基本面判定、體質分、新聞分（在選股名單裡直接用；不在的用快取或現抓財報重算）。
2. 補算上次之後每個交易日：開盤先成交前一天的預約單（先賣後買）；收盤做**價格規則**——止損（收盤 ≤ 首批價 50% → 預約全出，之後等止損價再跌 30% 且基本面通過才再進）；加碼（上一批價再跌 20% 或上漲後回落 25%，且基本面要通過）。
3. 最新一天做**滾動調整**（產生預約單）：
   - 汰弱：基本面「排除」或新聞紅線 → 全出；體質分（基本面與消息按 40:20 重新正規化）< 45 → 全出；基本面「警示」且新聞分 ≤ 30 → 減碼一半（每檔一次）；單檔 > 總資產 30% → 減到 25%。非止損的全出，30 天內不買回。
   - 評分加碼：總分 ≥ 72、還有批數、現價不比上一批高 10% 以上、距上次買進 ≥ 10 天 → 加下一批。
   - 補位：空出的名額由該類型排行（總分 ≥ 60、基本面通過、無紅線）由高到低補；**同一產業（Yahoo sector）最多 2 檔**（兩類型合計，產業未知不限），超過的跳過並記在日誌。
4. **金額依評分**：各檔目標總額 = 類型預算 × 權重，權重 ∝ max(總分 − 55, 5)，單檔不超過等權 2 倍；每檔仍分三批 2:3:4（第一批 = 目標 × 2/9）。分數越高買越多；分數降低後，之後的加碼也會變小。
5. 寫入：淨值與**當日損益**（對照 SPY）、每檔當日漲跌、累計已實現／未實現、**每筆交易的理由**（`trades[].why`，含訊號日 `signal` 與開盤價 `open`）、**當天操作日誌**（`journal`，「預約」「成交」「[調整]」）。同一天重跑會重算當天的 [調整] 預約單。

**限制（解讀績效時務必注意）**
- 價格規則會補算每個交易日；基本面／新聞／排行的判斷只在每次執行當下（最新一天）做，所以若某天漏跑，期間的基本面變化要到下次才反映。
- 第一批預約單要等下一次執行（資料多一個交易日）才成交，所以建倉第一天淨值全是現金。
- 樣本小、時間短；沒有止盈，績效是「抱著、只靠止損與汰弱出場」的結果。
- 評分加碼、體質分 45、新聞分 30、集中度 30%、同產業 2 檔、滑價 0.3% 等門檻是新設的判斷值，沒有回測。
- 房地產（如 MRP、ADAM）仍在成長型排行裡，尚未排除（待阿紘決定）。
- 2026-10-22 當天曾先後用「固定 2/3/4 萬、收盤成交」(v1)、「依評分、收盤成交」(v2) 建倉，都已作廢，改成上述 v3 並重新建倉。

## 18. 2026-10-28 輔助工具（不改任何交易規則）

來自外部審查建議，只挑對個人使用有價值、且不改阿紘規則的四項：
1. **回測成交假設**：`Rules.exec_lag`／`Rules.slippage`，`backtest(..., opens=)` 支援「訊號後隔日開盤成交＋不利滑價」；預設值與舊行為完全相同（0／0.0，已用隨機資料驗證輸出一致）。`run_backtest.py` 的 job 用 `exec_variants` 比較不同假設，並加上「參數敏感度」網格（進場 15–30%、加碼 12–30%、止損 40–60%）。Firstrade 美股無手續費，所以沒有加手續費項。
2. **額外進場條件，一次測一個**：`gates`＝大盤在 200 日線上／個股 200 日線上揚／近 20 日強於大盤／已脫離 20 日低點 5%。只限制「新一輪首批」，加碼與止損不受影響。測完是否採用由阿紘決定。結果顯示在交易系統頁「歷史回測」分頁（`backtest_realism_*`、`backtest_sensitivity_*`、`backtest_gates_*`）。
3. **正股＋期權合併曝險**（報酬日曆「目前持股」）：期權以標的歸戶，曝險＝權利金現值（最大虧損）；大類／細分產業每列拆「正股／期權權利金」，新增「單一標的曝險」前 10 名（>8% 標警示）。只顯示、不阻擋。
4. **基本面品質提示**（`fundamentals.quality_flags`）：單季營收年增率 vs 近 4 季、獲利但自由現金流為負、應收帳款成長遠快於營收。只寫進 `metrics`／`notes`（前綴 ⚠），**不影響判定與評分**；`fundamentals_cache` 的 v 維持 2，舊快取沒有應收帳款資料就不提示，隨 TTL 自然更新。
